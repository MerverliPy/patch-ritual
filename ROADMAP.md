# ROADMAP.md

## Phase 0 — Repo Operating System + Skeleton
### Objective
Create the Claude Code-native repo structure, memory system, and technical skeleton needed to execute the MVP without context drift.

### Deliverables
- root operating docs
- `.claude/` settings, skills, and agents
- monorepo folder skeleton
- app/package boundaries
- phase plans
- initial verification templates

### Outcome
The repo is ready for fresh-context Claude Code execution.

---

## Phase 1 — Auth, Repository Selection, Release Import
### Objective
Establish one creator, one repo, one release draft.

### Deliverables
- GitHub sign-in
- repository selection
- release list
- release import and normalization
- draft release object persisted in storage

### Outcome
A creator can connect GitHub and create a usable release draft from real source data.

---

## Phase 2 — Creator Draft Flow + Ritual Generation
### Objective
Turn the imported release into an editable ritual draft.

### Deliverables
- creator input form
- theme selection
- optional cover image
- ritual generation engine
- draft preview and editing

### Outcome
A creator can shape and approve a ritual draft before publishing.

---

## Phase 3 — Public Ritual Publishing Loop
### Objective
Deliver the public audience-facing ritual experience.

### Deliverables
- public ritual page
- publish flow
- republish flow
- shareable URL
- mobile-safe presentation

### Outcome
A creator can publish a ritual and share it with fans.

---

## Phase 4 — Audience Response + Analytics + Workflow Hardening
### Objective
Complete the MVP feedback loop and validate it fits real release behavior.

### Deliverables
- reactions
- comments / guestbook
- basic analytics
- completion / reach signal
- speed tuning and friction removal
- end-to-end verification

### Outcome
The product proves whether creators and audiences actually use the loop.

---

## Phase 5 — Post-MVP Differentiation
### Objective
Add the highest-value improvements only after the MVP loop works.

### Deliverables
- creator archive
- better social sharing
- saved creator defaults
- better highlight ranking
- optional voice note input

### Outcome
The product becomes more distinctive without changing its core shape.

## Build Order
1. Phase 0
2. Phase 1
3. Phase 2
4. Phase 3
5. Phase 4
6. Phase 5 only after MVP signal

## Stop Rules
Do not start post-MVP work unless:
- repeat publishing exists
- creators share the ritual after real updates
- audience reaction behavior is visible
